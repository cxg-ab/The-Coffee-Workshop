the-coffee-workshop motion audit

2026-07-29

🔴 Critical: 2 · 🟡 Important: 5 · 🟢 Opportunities: 4

Primary: Jakub Krehel — Production Polish

The accessibility foundation here is genuinely strong — stronger than most themes. A global prefers-reduced-motion reset sits unlayered at the top of the stylesheet, and animations.js independently gates every GSAP timeline behind the same query with a live change listener. That is belt and braces, and it is correct. The slop check is also mostly clean: no pulsing indicators, no bouncy springs on utility actions, and hover-scale appears exactly once in the whole codebase — well under the threshold that marks a generated UI. What is wrong is not taste, it is cost. Two systems animate the sticky header's height on scroll, and one of them desynchronises the --tcw-header-h variable that the bean-roast stage sizes itself from. Every internal link is intercepted and delayed 350 ms before the browser is even told to navigate. And the ambient background blobs animate border-radius underneath a 52 px blur, forever. None of these read as "nice animation" to a visitor — they read as a site that stutters. That is the opposite of what this motion is for.

Issues to Address

🟡 Important

One 1000 ms reveal applied uniformly to 25 elements, including legal and account copy

Every [data-reveal] gets the same y: 56, scale: 0.96, duration: 1, power3.out. It is used 25 times across 13 templates — including three blocks on the policy pages and five in the customer order template. This trips two anti-checklist categories at once: uniform-fade-in (threshold is 4 distinct components; this is 13) and motion-on-mount-for-static-content.

A refund policy should not slide up and scale in. And 1000 ms is double the top of the production band even by the permissive reading — the visitor waits a full second for text they are trying to read.

🟡 Important

Ambient blobs animate border-radius under a 52 px blur, infinitely

.about-liquid-blob runs an 18 s and a 22 s infinite alternate animation whose keyframes change border-radius as well as transform. Border-radius is not a compositable property, so each frame repaints the element — and because the element carries filter: blur(52px) at up to 380 px square, each repaint re-runs the blur. That is continuous GPU work on every page carrying an About or glass section, for as long as the page is open.

will-change: transform, border-radius makes it worse, not better: the border-radius hint does nothing useful and the declaration pins a permanent compositor layer. Drop border-radius from both the keyframes and the hint — the drift and scale alone read identically.

🟡 Important

Unthrottled mousemove creating two overwriting tweens per event

The hero 3D tilt fires gsap.to(visual, …) and gsap.to(orbs, …, stagger: 0.04) on every pointer move, each with overwrite: true. Overwrite forces GSAP to scan and kill existing tweens on those targets before creating new ones — so a 120 Hz mouse means roughly 240 tween constructions and 240 overwrite scans per second. The magnetic buttons repeat the pattern per element.

gsap.quickTo() exists precisely for this: it builds one reusable tween and just retargets its value, which removes the allocation and the overwrite scan entirely while producing the same settle.

🟡 Important

Underline reveal animates width

.about-value-card::before transitions width from 0 to 100% over 450 ms on hover, focus-within, and scroll-in. Width is a layout property — every frame triggers layout, then paint, then composite, instead of composite alone.

The easing curve is already the right one. Swap the animated property to transform: scaleX() with transform-origin: inline-start (which keeps the RTL mirroring you get from the existing inset-inline-start) and the same visual runs on the compositor.

🟡 Important

Two scroll authorities: CSS scroll-behavior: smooth and Lenis are both active

html { scroll-behavior: smooth } is set globally, while Lenis runs its own RAF-driven smooth scroll on fine-pointer devices. Lenis's own guidance is to remove the CSS property, because both intercept programmatic scrolling and fight over the same anchor jump.

This is reachable in the theme today: the skip-link and the footer's in-page links are exactly the anchor-jump case, and scroll-padding-top is tuned against the header on the assumption of a single authority. Let Lenis own scrolling when it is active and keep the CSS property for the coarse-pointer path where Lenis bails out.

Emil Kowalski — Restraint & Speed

What's Working Well

  • ✓ The header scroll listener is requestAnimationFrame-throttled and registered { passive: true } — textbook — sections/header.liquid:142–149
  • ✓ shouldPageTransition() correctly excludes modified clicks, _blank, downloads, forms, the cart drawer, checkout and logout — the exclusion list is well considered — assets/animations.js:213–229
  • ✓ Hover-scale appears exactly once in the entire codebase (nav-menu.liquid:62), far below the ≥3 threshold that flags hover-scale-on-everything
  • ✓ No pulsing, glowing or breathing indicators anywhere — this is the single most common slop tell and it is completely absent
  • ✓ The bean-roast scrub is a rare, once-per-visit showpiece, which is exactly where expressive scroll motion earns its place

Issues to Address

🔴 Critical

Every internal navigation is blocked for 350 ms before the request starts

initPageExit() intercepts clicks on all same-origin links, calls preventDefault(), plays a 350 ms fade-out timeline, and only sets window.location.href in the timeline's onComplete. The browser is not told where to go until the animation has finished.

Navigation is the highest-frequency action on a store — every product card, every collection pill, every nav item. This adds 350 ms to all of them, before any network work begins, and the delay is pure cost: nothing is fetched during it. On a slow connection the visitor then stares at a filled overlay with no progress signal. Emil's frequency gate is unambiguous here.

Start the navigation immediately and animate the arrival instead — initPageEnter() already does exactly that, and already handles the sessionStorage handoff.

🔴 Critical

Two competing header-shrink systems, both animating height on the sticky header

There are two independent implementations running at once. header.liquid's inline script toggles is-compact past y > 40; animations.js creates a ScrollTrigger that toggles is-scrolled at top -60. Both style .tcw-header__inner's height, to different values (3.5rem vs 4rem), with equal specificity — so the winner is decided purely by source order, and is-scrolled is dead weight that still costs a ScrollTrigger on every page.

The live one animates height with transition: height 0.3s ease on a position: sticky element. Height is a layout property, so for 300 ms at the very moment the visitor starts scrolling, the entire page below the header re-lays-out every frame. This is a strong candidate for the scroll stutter reported earlier. (The easing is also bare ease, the one curve to avoid.)

There is a second-order bug. The script sets --tcw-header-h instantly to the compact value while the header itself animates over 300 ms, so every consumer of that variable jumps ahead of the header. One of those consumers is the bean-roast stage: --br-stage-h: calc(100dvh - var(--br-header)). Its CSS box changes height mid-scroll, but size() only listens for resize and visualViewport events — not for a custom property change — so the canvas backing store is never re-computed and the painted frame is left stretched against its box.

Lens Reference Summary

Which lens was referenced most: Jakub Krehel — Production Polish

Why: This is a shipped e-commerce storefront where visitors browse repeatedly, so motion has to survive the tenth viewing rather than impress on the first. Emil carried the two Critical findings because both sit on navigation and scrolling — the highest-frequency interactions on a store — and Jhey stayed selective, applied only to the roast showpiece.

If you want to lean differently:

  • To follow Emil more strictly: remove the page-transition overlay entirely rather than reworking it; cut the reveal duration to 180 ms; drop stagger from every list including the product grid; remove the hero 3D tilt and magnetic buttons, which are pointer-only delight on a high-traffic page.
  • To follow Jakub more strictly: add the blur step to every enter you keep; give the drawer, modal and filter panel a shared easing token instead of three hand-written curves; audit optical alignment on the icon buttons in the header and cart drawer.
  • To follow Jhey more strictly: push the roast scrub further with linear() pacing and a caption that animates on stage change; move the Arabic word field to scroll-driven timelines so it responds to the reader rather than looping on a timer.
